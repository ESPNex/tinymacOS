# Architecture notes

## The handoff

`boot/loader.c` is a PE32+ EFI application produced using GNU-EFI startup and firmware protocol definitions. The ISO has an EFI-platform El Torito entry pointing to a 40 MiB FAT16 boot volume. `/EFI/BOOT/BOOTX64.EFI` and `/System/Kernel/kernel.elf` occur in the readable ISO tree, the boot FAT and a 20 MiB installation ESP embedded as `Install.esp` only on the CD boot FAT. The ESP contains just the runtime binaries, no recursive installer payload. Device-path partition signature and payload presence distinguish disk and CD boots. The loader opens the image's own filesystem, validates ELF headers/segment extents, reserves the linked physical range at 64 MiB, copies `PT_LOAD` bytes and zeroes BSS. It prefers 1280×800, then 1024×768 when available (supported range: 800×600 to 1280×1024, 32-bit RGB/BGR GOP), records pitch, and discovers the ACPI RSDP. A bounded GetMemoryMap/ExitBootServices retry handles obsolete keys. There are **no runtime or boot service calls** after successful exit. `arch/entry.S` selects a kernel-owned stack before calling C.

## CPU and memory

- Long-mode GDT selectors: kernel CS `08`, DS `10`; user SS `1b`, CS `23`; 64-bit TSS `28`. The TSS has RSP0, a double-fault IST and an absent I/O bitmap. IOPL remains zero. The IDT covers 256 vectors. User exceptions terminate the faulting process; kernel exceptions print vector/error/RIP/CR2 to COM1 and halt on a graphical panic screen.
- The PMM bitmap is populated **only from conventional UEFI memory** from 1 MiB through the first 4 GiB. “Managed memory” excludes firmware, device ranges, the loaded kernel and reserved pages; it is not a fabricated installed-RAM figure. Pages are cleared on allocation. A coalescing 1 MiB kernel heap holds variable-sized objects such as draw queues.
- Each process owns its PML4, with a shared supervisor-only low identity map. Kernel code is RX; read-only data is R/NX, writable data and the remaining identity map RW/NX. CR0.WP and EFER.NXE are active. Every user leaf is mapped in a separate PML4 branch. Equal user virtual addresses in different processes have different backing pages. Mapped stacks and heap are RW/NX; unmapped gaps provide stack guards. Kernel accesses to a user buffer check the complete page range and requested permission before the copy. No application maps the physical framebuffer or the boot-file extents.
- Single-core preemptive round-robin: up to 23 non-idle task slots, 13 simultaneous process slots besides the kernel. Runnable/sleeping/dead states, per-task interrupt stacks, integer context and FXSAVE64/FXRSTOR64 x87/SSE state. AVX is not enabled. User threads share the owning process root, fd table and IPC state but have separate stacks. Idle and an independent RTC-sampling kernel thread run at CPL0. The 100 Hz PIT is routed by the I/O APIC when ACPI MADT is valid; PIC fallback exists but is not the release validation target. The current kernel is nonpreemptible inside ordinary syscalls; there is no SMP, demand paging or swapping.
- Page tables, user frames and the window command buffer are reclaimed following exit on a different address space. Allocations are tracked per process. The CPL Probe executes `mov %cs`, calls the actual SYSCALL instruction, verifies its cookie and measures CS again. The timer interrupt log shows the **hardware-saved interrupted CS**, in contrast to the SYSCALL return frame constructed by software.

## ELF and syscall ABI

All executables are little-endian x86-64 ELF64 `ET_EXEC`. The linked user base is `0x0000008000000000`; the upper limit is base + 1 GiB. Page-aligned `PT_LOAD` segments have separate RX, R/NX and RW/NX permissions; writable+executable segments are rejected. Kernel/user objects are standard ELF64 `ET_REL`; kernel and app linker scripts define their distinct layouts. Userspace ELFs are built individually, stripped, then enclosed in a read-only boot archive. The loader in `kernel/sched.c` maps a fresh instance for each spawn. `/Applications/*.app` files are manifests naming these installed executables, not scripts or mutable executable file contents. Arbitrary ELF files on the user volume are not loadable in this release.

The public interface is `include/abi.h`. `RAX` carries the syscall number/result; arguments A–D are `RDI, RSI, RDX, R10`. `RCX` and `R11` are clobbered. Errors are `-1` unless otherwise specified. In particular, negative values must be checked before treating a return as a user pointer or record count. The kernel programs EFER.SCE, STAR, LSTAR and FMASK. Entry switches from user RSP to the current thread's kernel stack before touching user memory. Return uses a validated-selector `IRETQ` frame, **not** an unchecked `SYSRET`. A kernel-only interrupt gate allows the RTC worker to sleep; no DPL-3 software interrupt gate is exposed.

| Area | Public operations and conventions |
|---|---|
| Tasks & time | `S_SPAWN(app,arg)` returns PID; `S_THREAD(entry,arg)` creates a user thread. `S_SLEEP(ticks)` sleeps, `S_EXIT(0)` ends the process, `S_EXIT(1)` ends a worker thread. `S_PS`, `S_TICKS`, `S_INFO`, `S_DEVICES` copy bounded records or return counters. |
| Memory | `S_ALLOC(bytes)` returns a page-aligned address, `S_FREE(base)` releases an exact tracked allocation. Maximum 32 active allocations and 8 MiB per request. |
| Files | `STAT/LIST/CREATE/REMOVE/MOVE` take bounded absolute paths; `OPEN(path,write)` returns a process-local fd; `READ/WRITE(fd,buffer,length)` return byte counts; `CLOSE(fd)` releases it. Paths, records and flags are documented in `abi.h` and `TINYFS.md`. |
| Native window clients | `S_WOPEN(width,bodyHeight,title)` registers one window per process; `S_WDRAW(commands,count,title,transition)` commits a copied frame and increments its generation. `S_EVENT(&event)` retrieves a routed event or returns zero. An accepted close ends the client and its window. |
| Desktop server only | `S_WLIST` returns descriptors; `S_WGET` copies a client's most recent command list; `S_INPUT` reads raw keyboard/pointer events; `S_SEND` delivers a bounded translated event. `S_PRESENT` submits a logical XRGB8888 buffer; B/C may specify a bounded damage rectangle, with C=0 for full scanout. Other apps are denied these capabilities. |

## Display and devices

`desktop/` is a Ring-3 program. It owns focus, stacking, positions, sizes, clipping, the cursor, menu dispatch and Dock state. Clients provide size-dependent rectangles, lines, text and image operations through a retained, validated-size **display list** (144 commands max per window). The server redraws into ordinary process memory and submits it to the kernel for scanout. Only the kernel performs GOP-memory writes; it skips unchanged 32-pixel spans and converts RGB/BGR if needed. There is no host window surface inside the guest.

### Native compositor (Aurora)

1. `desktop/gfx.c` decodes embedded QOI images once, uses a TFN2 Latin and symbols alpha-font atlas and software-drawn icons. Semantic inks select one of five complete palettes, independently of the selected wallpaper. Clients can also submit `C_IMAGE` (curated asset ID), `C_BUTTON` and `C_GLASS`: **no client pointers are interpreted as textures**. Paths and documents stay with the client process.
2. `desktop/glass.c` captures the current composition (including previously drawn windows). It takes four samples per 4×4 cell, then applies separable `[1,4,6,4,1]/16` convolution. Bilinear reconstruction, a signed rounded-edge approximation, displaced samples with RGB edge splitting, tint, highlight, supersampled coverage and shadow produce the optical material. Opaque mode bypasses capture/blur and uses solid materials.
3. `desktop/main.c` builds z-ordered resolved window textures in compositor-owned, tracked user allocations. Each cache key includes client generation, focus, geometry and the lower scene layers intersecting its blur footprint. Static chrome tiles are cached separately. A moving/zooming window resamples its resolved appearance rather than tracing a physical lens at every transformed pixel. Animation modes are visual approximations, not ray tracing.
4. `desktop/motion.c` animates these actual textures: eased open/close, zoom and restore, narrowing contraction into the Dock. Client transition hints slide or dissolve content inside a fixed frame. `desktop/shell.c` animates Dock magnification, launch bounce, positioning and overlays; handles keyboard search, the calendar widget, real window thumbnails, controls and power confirmations. Shadow and screen damage are clipped. During pointer-only movement, two damaged rectangles update the old and new cursor. Reduced motion skips geometric transitions; on TCG the frame count depends on CPU load and overlapping client updates.
5. One native ELF per app, one front window per process, independent event queues. The ten launcher IDs correspond to the canonical English bundle filenames in `bundlename()` and Italian labels in `appname()`. There is no AppKit, Metal, Quartz, POSIX compatibility layer or macOS binary compatibility. The application library can launch all ten even when not all are pinned to the Dock.

`SysInfo.busy_ticks` and `ProcInfo.cpu_ticks` are sampled at the PIT interrupt. Non-idle ticks include the kernel RTC worker; user process totals are per owning task group. Monitor Attività computes interval busy/total and sorts on cumulative per-process ticks. This coarse sampling can legitimately give a just-started or sleeping process zero ticks. The graph is not synthesized activity.

The kernel device registry records successful native drivers and exposes their names/classes to Terminal's `devices`. `drivers/platform.c` validates ACPI checksums, reads MADT routing and the QEMU-style FADT/DSDT S5 package; the latter is a limited reader, not a general AML interpreter. PCI functions are enumerated using configuration mechanism 1. `drivers/pci.c` locates AHCI/xHCI by class and maps register BARs (including 64-bit addresses) into supervisor-only uncached MMIO. `drivers/xhci.c` resets the controller, provisions DCBAA, command, event and transfer rings, addresses devices, parses configuration descriptors, selects boot protocol and arms interrupt-IN endpoints. The PIT drains USB completion events; `drivers/input.c` translates 8-byte keyboard and relative pointer reports into events. No 8042 access or firmware keyboard calls; direct-root devices only, no hot-plug/hub support. `drivers/ahci.c` takes over live SATA ports with command-list/FIS/table DMA buffers, IDENTIFY, READ/WRITE DMA EXT and FLUSH CACHE EXT; ATAPI optical ports are not install targets. Reboot uses Q35 reset control (CF9); power-off uses ACPI S5. A command timeout is a disk error, not a successful write. No invented Wi-Fi, volume or battery indicators.

## Aurora boot, identity and session boundary

The loader switches GOP **before** file I/O, paints the grayscale coverage mask from `assets/fruit.inc` (derived from the supplied `assets/apple.svg`), and advances the track below it in relation to bytes received during bounded reads (up to 128 KiB at a time). Segment loading ends the firmware portion at 60%; CPU, memory, platform, filesystems, input/interrupt and scheduling milestones advance it to 100%. The next frame comes from the Ring-3 login UI, not a stored screenshot. Firmware's own startup screen can appear before our loader. No firmware APIs are called after ExitBootServices.

`Boot` carries the boot binaries and the optional CD installer payload in explicitly retained EfiLoaderData pages below 4 GiB, with byte lengths and optional EFI RNG salt material. The physical allocator does not free EfiLoaderData. The supervisor-only VFS backend in `fs/bootfs.c` routes `/System/Kernel` to a read-only tree, with IDs starting at 1024 to disambiguate it from TinyFS. Kernel/loader FDs address the actual retained input buffers, not live text, heaps or writable supervisor data. The namespace has exactly two files; source code and link maps are not present. `S_SEEK(fd,absoluteByteOffset)` allows an offset up to EOF. Each `S_READ` is limited to 8192 bytes but repeated reads cover a whole boot object. All mutations of that namespace are denied. Finder has separate FDs for pagination and incremental SHA-256, and closes both when leaving the inspector. The shell's `shasum` is a separate client of the same ABI.

`kernel/session.c` owns SETUP, LOCKED, OPEN and BROKEN states. Blank account records enable first enrollment. A valid record always starts locked. Wrong attempts require a fresh PBKDF2 and impose a volatile 1–16 s retry interval. Only the trusted compositor may request status (`S_SESSION`), begin verification (`S_AUTH_BEGIN`), do bounded KDF work (`S_AUTH_STEP`), or lock (`S_LOCK`). Before OPEN, ordinary clients cannot spawn or enumerate apps, access files/fds/windows/preferences, or get their start arguments. They are not dispatched by the scheduler while locked. Only the compositor, diagnostic probe, idle and RTC worker exist at boot; Finder is explicitly spawned **after** successful authentication. Login consumes raw input without routing it to an application; submitted secret buffers are cleared. Locking retains process memory so unsaved work can resume. The user-selected name is the local display name; the single home stays `/Users/User` for compatibility. This is not multiuser isolation, disk encryption or an offline security boundary. The trusted loader has no signature verification.

### Login activity (1.2.1)

The UEFI boot track is unchanged. Once `S_AUTH_BEGIN` accepts a request, the login form is replaced with a monochrome 12-spoke indicator. Rounded stroke coverage is computed once in fixed point with 4×4 subpixel sampling. A white alpha trail steps clockwise every eight 100 Hz PIT ticks; phase depends on elapsed time, not the KDF completion percentage. Reduced Motion uses a stationary indicator and status message. Both success and rejection dismiss the indicator immediately, without delaying verification or weakening the session boundary. Menu, About and splash assets derive from the same user-provided SVG path.

### 1.2.2: salt provisioning without a hardware RNG

`session_init` first classifies both account sectors. **Only SETUP** prepares one salt in kernel RAM. `kernel/salt.c` tries the EFI RNG result, CPUID-guarded RDSEED/RDRAND with bounded retries, then the freestanding CPU Jitter RNG (3.4.1; source and origin under `crypto/jitterentropy/`). The timing source measures variations in memory and hash computation; this is not hashing the current time once. With an advertised TSC the upstream core is built at `-O0 -fwrapv`, with 3× oversampling, enabled start-up and continuous health checks and SHA3-256 conditioning. No threading, user inputs, RTC-only fallback or guest network service. A failed check discards the automatic candidate. Health checks cannot guarantee entropy in a hostile hypervisor or identical deterministic snapshots; this is an experimental system, not a validated cryptographic module.

When no automatic source is usable the trusted compositor requests a fresh host-generated code **before** password entry. `S_SETUP_CODE` is restricted to the compositor in SETUP, only when a salt is missing; malformed and repeated-half codes are rejected. Only public salt material is transferred, never a reset credential. The call grants no access and writes no account sectors. The original PBKDF2 verification, storage format and corrupt-record behavior are unchanged. Opening an existing account requires no new entropy and never presents the code field. The Linux launcher offers a host-backed virtio RNG to firmware that understands it; `TMC_CPU` and `TMC_RNG=none` allow testing CPU/device-limited configurations.

## 1.3: the installer is a desktop client

`userspace/installer.c` is a separately linked, unprivileged executable. `S_INSTALL` is available only to the authenticated installer process. A query returns descriptions/eligibility, not a block handle. Other operations select a discovered disk by index, advance a bounded amount of work, or cancel the pre-write scan. `fs/install.c` is the sole author of partition writes: the client cannot supply an LBA, length, FAT image or data pointer for arbitrary writes. UI progress reflects actual completed sectors. Disk size and eligibility are checked again on confirmation, then every sector is checked for zero **before the first write**. The authenticated TinyFS snapshot is taken within one non-preemptible kernel call. The ESP and TinyFS extents are flushed and compared byte-for-byte before the GPT backup, primary table/headers and protective MBR are committed and read back. A provisional or damaged target is not erased automatically. Cut power is not an atomic transaction; use a fresh disposable target after interruption. On disk boot the TinyFS volume must belong to the GPT whose ESP unique ID matches the EFI boot device path. An unreadable installed account cannot silently enroll again from a fresh RAM volume.

Finder answers a compositor-issued context request with an action bitmask; the kernel stamps the PID and the desktop validates the pending request token and focused window. The compositor draws a screen-clamped native popup. Desktop, text editing and window actions are separate from file actions. Mutations still use ordinary checked filesystem calls. The menu apple uses the supplied SVG rasterized for **16 px** in a 24 px cell; the 94×108 boot mask is unchanged.
