# TinyFS v1

A small single-user filesystem shared by every app. It is independent of the read-only FAT EFI system volume. The kernel block interface is `read(lba,sector)`, `write(lba,sector)`, capacity. An installed Q35 SATA disk has a protective MBR, primary and backup GPT, a bootable FAT16 ESP (LBA 2048–43007), and a separate TinyFS data partition starting at 43008. **All LBAs below are relative to that data partition**, not physical disk LBAs. The EFI ESP unique ID from the boot device path selects the matching data disk. A CD without a legacy volume uses identical RAM sectors. A raw 1.x TinyFS may be imported into RAM from a second SATA disk during CD boot: even app-manifest migration changes the RAM copy, never the original.

## On disk (little endian, 512-byte sectors)

- **LBA 0**: bytes 0..7 `TINYFS1\0`; u32 version `1` at 8, node count `96` at 12, data sectors per node `16` at 16, initialized flag at 20. `0` opts in to first-boot seeding; `1` means mount existing data. The filesystem currently uses 1,552 sectors; the rest of the data partition is reserved. Old 8 MiB data-only volumes used exactly the same relative layout. `tools/mkdisk.py` creates an all-zero virtual installation target exclusively, not a preformatted volume.
- **LBA 1..12**: 96 fixed-size, 64-byte nodes. Offsets: `u8 kind` (0 unused, 1 directory, 2 file), `u8 read_only`, `u16 parent`, `u32 length`, `u32 generation`, `char name[48]` (NUL-terminated), `u32 reserved`. Node 0 is root. LBAs 13 and 14 are private account records in Aurora; LBA 15 remains reserved. Entries are identified by index; filenames are case-sensitive.
- **LBA `16 + id*16`**: a private 8,192-byte extent per node. The logical length is authoritative. Reading beyond EOF returns zero bytes. New files start empty. A write updates the logical length to the descriptor's new offset; opening for write alone does not truncate. Ordinary writes through a fresh fd replace the document. Deletion invalidates the node; its generation changes on slot reuse so stale descriptors cannot access the replacement.

## Semantics and limits

Paths must fit in 144 bytes including NUL. Components fit in 48 bytes including NUL. Lookup handles repeated separators, `.` and `..`. Creating an existing name fails. Moving a directory into itself or its descendants fails. Nonempty directories cannot be deleted. Node metadata is changed by bounded kernel operations, not by direct app access to disk. Each process has 12 descriptor slots. Mode is single-user writable versus read-only; there are no Unix owner/group bits, timestamps, hard links, symlinks or ACLs. A short/capacity/permission error is reported rather than silently successful persistence. Never use experimental TinyFS as the only copy of important files.

Each sector write is followed by SATA cache flush before success; data is written before final length metadata. This is **not** a journal or an atomic multi-sector transaction. Loss of power mid-write can damage a document. The mount checks the header, node types, bounds, names and parent chains. It does not implement repair. Back up `state/system.raw` with the VM off.

The initial tree contains `/System/{Kernel,Libraries,Configuration}`, `/Applications`, `/Users/User/{Desktop,Documents,Downloads,Pictures}` and `/Volumes`, plus `Welcome.txt` in the user's home. `/System/Kernel` is a read-only boot-volume view, separate from these inode extents. Only the kernel and EFI loader bytes appear there; no executable is copied into a small writable inode. The kernel-managed `/System/Configuration/Appearance` record is empty on a fresh unchanged volume; after a preference change it contains five bytes: theme (Chiaro, Scuro, Glaciale, Boreale, Rame = 0..4), wallpaper (Prisma, Alba, Laguna, Aurora, Prisma glaciale, Aurora boreale, Rame vespertino = 0..6), Dock position (bottom=0, left=1), reduced motion (0/1), opaque materials (0/1). The File Manager, Terminal and TextEdit all use the same inodes; no per-app mock filesystem exists.

## Upgrading copies of TinyOS 1.0 disks

Orizzonte still uses TinyFS v1. A three-byte 1.0 preference record loads with both new flags off. Changing a preference writes the five-byte form. On an initialized, validated volume, `migrate_apps()` visits known system-managed records in `/Applications` only. It refreshes localized payloads, reuses the prior About inode and adds any missing read-only app manifests if there are free nodes. The signed-in user's directories, welcome file and documents are **not reseeded or rewritten**. If the volume is full, the serial log reports skipped manifest updates; the compiled-in app registry remains usable. Do not downgrade a modified data image in place. Always retain an offline backup.

Calendar reminders are ordinary small text files (`/Users/User/Documents/Agenda/YYYY-MM-DD.txt`). A short entry can be entered in Calendario; longer existing notes open in TextEdit to avoid truncation. Gallery artwork lives in the immutable OS image, not in these small document extents.

## Account sectors (1.2)

Two equal 512-byte records, outside all application-visible file extents. Offset 0: `TMCUSER2`, offset 8: LE32 version 1, offset 12: LE32 120000, offset 16: NUL-terminated display name (32 bytes); offset 48: 16-byte salt, offset 64: 32-byte PBKDF2-HMAC-SHA256 verifier, offset 96: 384 reserved zero bytes, offset 480: SHA-256 of the preceding 480 bytes. The trailer detects damaged records, not hostile offline modification. In 1.2.2 a blank account takes a 16-byte salt from EFI RNG, RDSEED, RDRAND, or the CPU Jitter RNG after its health tests. If none works the setup UI accepts a one-time, host-generated 32-hex-character code for the public salt only. This does not create or unlock the account and is unavailable with an existing or broken record. Existing accounts always use the salt already stored in their record. No fixed seed, clock-only seed, user name or password is used as a substitute for entropy. Backup sector is written first, then primary, then the primary is read and verified. Any valid copy can be used; two invalid *nonblank* records never trigger automatic enrollment. Both zero indicates a new account, including an older disk with untouched reserved sectors. In RAM live mode the identical logic uses temporary RAM sectors. No plaintext password or disk encryption key is stored. Applications cannot open these sectors by name or through a raw-device syscall.

Fresh settings default to Chiaro with the Rame vespertino wallpaper. Old 3- and 5-byte appearance records preserve their existing wallpaper indices. There is no journal, encrypted home, forgotten-password recovery, or fallback credential. Someone who can edit or replace the disk/OS offline is outside the model.
