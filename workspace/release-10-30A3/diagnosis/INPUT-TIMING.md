# Optical Recovery input investigation (not a hardware certificate)

- Original optical Block I/O firmware: no USB_IO handles. Native R selection failed on the published 30A2 ISO. The added, unchanged upstream UHCI/EHCI/UsbBus modules restore actual firmware USB enumeration and native Recovery selection.
- Initial supplementary test used 20 ms loader pulses and 40 ms ordinary QMP key holds. Boot pulses could be missed under TCG. In Recovery, traces contained missing make/break states; a missing Return break could leave repeated blank prompts. The absence of tesseract was a secondary assertion-formatting error, not evidence that the actual framebuffer was correct.
- A 180 ms hold with change-only HID did not make the initial keyboard test reliable. Requesting periodic full Boot reports with HID SET_IDLE=8 (32 ms) improved state refresh and allowed the initial production mouse/tablet command tests to pass. Host sanitizer contracts execute the actual keyboard code and verify no duplicate presses from identical reports, release cancellation, local repeat, Italian/AltGr decoding and tolerated optional SET_IDLE STALL.
- Broader tests still demonstrated occasional missing characters with 40/120 ms QMP holds (e.g. `swvers` and `s_vers`). A diagnostic-only direct framebuffer experiment, with change-only reports restored, did not resolve the issue. That screen change is **not in production**. There is no basis for calling the BIOS GOP blit the established cause.
- Final supplementary automation explicitly allows the firmware HCD completion timer/emulated device state to be serviced: ordinary keys are held 300 ms with a separate release interval, below local repeat; loader selection pulses are 120 ms, after the observed OpenCore picker has autobooted. The receipt records this timing. This is a functional pointer/Recovery test, **not a keyboard throughput/latency test**. The native live/installed and Italian regression suites keep their own independent fixtures and timings.
- Final acceptance must include actual R/F12 entry, both pointer types, Terminal/Continue clicks, `sw_vers` and `diskutil info /` (optical origin) in fresh cold boots of the exact production ISO. Earlier incomplete/failed test runs are not counted as PASS.

No new ASRock physical test was performed. These findings do not establish the physical cause of its stationary USB mouse, nor certify a PS/2 firmware selector on that board.
