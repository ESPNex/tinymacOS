# Linux input compatibility — implementation status

Current source milestone: complete original `hid-generic.c` and `hid-input.c` compile and execute through a bounded transport/event-sink API in host tests. **Native USB endpoints still do not call this new path.** Full Linux controllers and remaining USB core/hub remain missing; PS/2 class-driver work is explicitly deferred by the latest user instruction.

The kernel compiles the complete, unmodified Linux v6.12 files **`usbmouse.c`, `usbkbd.c` and USB core `urb.c`/`config.c`**, plus the complete unchanged EHCI `qtd_fill` function. `vendor/linux-v6.12/manifest.json` pins source/license hashes; upstream notices remain intact. Boot drivers and the separate shim are GPL-2.0-or-later; `urb.c` is **GPL-2.0-only**. The keyboard translation unit includes the byte-exact driver and exposes its physical keycode table to the input adapter.

The original upstream `urb.c` now supplies allocation/init, reference acquisition/release, submission validation, interval normalization, unlink/kill/poison/block, and all anchor operations. It replaces the former handwritten `usb_alloc_urb`, `usb_free_urb`, `usb_submit_urb` and `usb_kill_urb`. Native compatibility services provide overflow-checked allocation, saturating references, real atomic/list/IRQ-lock operations and predicate/timeout waits. Optional KMSAN, dynamic debug and atomic-sleep debugging instrumentation are disabled; this does not replace scheduling or transfers. Waits use the current polled runtime, not a general Linux sleepable scheduler. On CPU0, a CPUID/PIT-calibrated TSC keeps timeout time advancing with interrupts disabled; this is not a cross-CPU/suspend timekeeping port.

**Important boundary:** `usb_hcd_submit_urb` and `usb_hcd_unlink_urb` are still a documented **native bounded backend, not Linux `hcd.c`**. Each binding exposes one logical interrupt-IN slot and one EP0-OUT slot, at most eight payload bytes. Unsupported SG/bulk/isoc/IN-control or a second active slot fails explicitly, before ownership transfer. Hardware DMA/queues remain owned by native xHCI/EHCI/UHCI. Logical URBs use core references and native giveback with anchor/callback ordering; a callback may resubmit or drop its final driver reference safely. The old Linux-shaped struct/API subset is not the complete Linux ABI.

Native enumeration passes actual received interrupt packets to the upstream Boot drivers. Mouse report IDs, wide axes, nonstandard wheel layouts and absolute tablets retain the descriptor-aware native path, **not** Linux generic HID. Allocation failure retains the native fallback. Registered keyboards merge held physical-key bitmaps/modifiers without a six-key aggregate limit, using the sole Italian layout. Invalid/rollover reports do not invent releases.

The original keyboard LED event/completion state machine submits through upstream URB core. The deferred adapter copies requests, drops the compatibility lock before native EP0 waits, and verifies binding generation plus submission serial before completion. Cancellation/disconnect/rebind cannot complete a freed or superseded URB. Platform suspend/wake enable is explicitly unsupported.

**Still missing:** complete Linux xHCI/EHCI HCDs, the rest of the general USB core/hubs and generic HID. This is not a complete Linux USB stack or release completion. Recovery remains separate: firmware mouse protocols, OpenUsbKbDxe keymap and the declared derived firmware PS/2 raw stream.

Tests: `tests/linux_usbmouse.c`, `tests/linux_usbkbd.c` and `tests/linux_urb.c` execute the original sources and actual shim under ASan/UBSan. Core tests cover allocation-size overflow, reference saturation, endpoint/state/packet/SG/control/interval validation, short packets, requeue, cancellation/poison, all anchor APIs, actual timeout/concurrent wakeup, endpoint-slot backpressure, driver-put while active and callback-free lifetime. Keyboard tests retain Italian/multi-keyboard/repeat/caps/LED/reentrant-control/ABA/STALL/leak checks. Guest receipts in `workspace/release-10.1.7-30B8/` check the ISO's actual KernelCache, linked upstream symbols and live submit/giveback counters, along with rendered mouse movement/Italian text and LED requests. QEMU success is not physical Bay Trail validation.

Mouse lifecycle integration also merges the held buttons of registered Linux-bound mice without replaying another device's motion/wheel. A second mouse's idle/release/unregister cannot cancel a drag still held on the first. Native xHCI/EHCI/UHCI error completions now reach the original upstream mouse IRQ through URB giveback. The affected device's buttons are released without manufacturing a successful report; recoverable errors resubmit for native reset, while terminal cancellation/shutdown statuses retire the logical URB. This does not add general controller hotplug. Registered PS/2 mice now join the shared button union; native allocation-fallback pointers still remain separate.

`tests/linux_mouse_lifecycle.c` checks 1,024 paired five-button states, signed independent X/Y/wheel, transient/fatal errors, cancel/reopen, teardown and leaks. The xHCI maintenance contract executes an actual native STALL/reset/rearm/resumed-motion path with the real Linux mouse/core attached. Two additional UEFI/BIOS guest profiles each attach two virtual USB mice and verify actual rendered Terminal-window dragging across both devices' press/release transitions. These are virtual-device tests, not physical Bay Trail certification.

## Four input paths: explicit completion boundaries

| Path | Actual Linux code linked and executed | Still native / missing Linux port |
| --- | --- | --- |
| USB mouse | Complete Boot `usbmouse.c`, core `urb.c`, EHCI `qtd_fill` | HCDs, remaining core/hubs and generic HID |
| USB keyboard | Complete Boot `usbkbd.c`, core `urb.c` | HCDs, remaining core/hubs and generic HID |
| PS/2 mouse | Complete `libps2.c`; complete original `psmouse` packet/report and IntelliMouse/Explorer detect functions | `i8042`, serio bus, native stream framing and remaining `psmouse` lifecycle/extensions |
| PS/2 keyboard | Complete `libps2.c`: setup/ACK/resend and RX dispatch | `i8042`, serio bus, `atkbd` decoder and runtime LED work |

The PS/2 library and its header are byte-exact upstream Linux v6.12, GPL-2.0-only. `compat/linux/ps2_protocol.c` includes the entire unit with a polled RX wait adaptation; only its initializer is namespaced to avoid the OS's existing `ps2_init(void)` symbol. The native i8042 byte writer and the new serio subset use real IRQ-preserving RX locks, a shared command mutex, monotonic timeout, and explicit native RX progress. There are no synthetic ACKs or successful placeholder writes. Commands validate parameter capacity and cannot reenter from receive callbacks. This is CPU0-polled command infrastructure, not a general Linux process scheduler/serio framework.

Kernel boot setup for both PS/2 ports now calls original `ps2_command`; mouse wheel negotiation uses original Get-ID handling, including the upstream non-ACK mouse-ID workaround. Subsequent input bytes pass through original `ps2_interrupt` before the native keyboard decoder and upstream mouse packet functions. The keyboard LED state machine remains nonblocking/native in timer context: Linux documents synchronous `ps2_command` as process-context-only, so it is deliberately not called from the PIT handler. Recovery is unchanged and firmware-only; these native PS/2 services are not linked there.

`tests/linux_ps2.c` executes actual original libps2 and adapter under ASan/UBSan: ACK/NAK/retry, keyboard/mouse IDs, absent ACK, partial reset response, sliced commands, RX locks, shared serialization, bounds/flags checks, parity/timeout abort, real timed wait, interleaved bytes and nested-command rejection. Two actual ISO guest profiles with **only PS/2 keyboard+mouse** verify Italian Shift/AltGr/accent/euro/Caps, LED acknowledgements, six exact rendered X/Y checks and visible bidirectional wheel scrollback. Two mixed guest profiles use PS/2 keyboard plus two Linux-bound USB mice for enrollment and rendered dragging. These functional checks do not make the remaining `atkbd`/`psmouse`/i8042 code into Linux drivers.

### Original PS/2 mouse packet engine (v9)

`psmouse-base.c` and `psmouse.h` are vendored byte-for-byte from Linux v6.12 (GPL-2.0-only). `psmouse-packets.inc` includes the complete unchanged standard button/motion/packet and `psmouse_process_byte` functions; `psmouse-detect.inc` includes complete unchanged `intellimouse_detect` and `im_explorer_detect`. Offline source checks verify both files against the original source ranges and SHA-256. `psmouse_input.c` supplies a declared field subset, not a binary Linux `struct psmouse` ABI, and routes the private detector's synchronous commands to the real AUX libps2 adapter. The rest of `psmouse-base.c`, serio bus, hotplug/reconnect/resync workqueue and touchpad extensions are **not** compiled/ported by this increment.

Kernel PS/2 mouse packets no longer use the native arithmetic decoder. Upstream handles the zero-byte sign quirk, full signed 8-bit IntelliMouse wheel (not a four-bit approximation), Explorer five buttons, vertical and horizontal wheel formats. Native first-byte alignment/overflow rejection and parity/timeout packet reset still bound the stream. Boot performs real Linux detector rate/Get-ID sequences; any libps2 command failure rolls registration back instead of reporting a successful probe.

Registered non-USB input pointers now share the held-button union with Linux USB mice, without fabricating a USB interface/URB. Relative motion is never replayed from the other pointer. Error/stop/unplug releases only the affected pointer. Horizontal wheel is emitted as `EV_SCROLL.b` (vertical remains `.a`); current desktop apps do not implement horizontal scrolling, so input delivery is not a claim of desktop horizontal-scroll support. USB/input frame counters remain USB-only.

Host ASan/UBSan executes both `-O1` and kernel-style freestanding `-O2`: 3072 signed-axis combinations, all 256 IMPS wheel bytes, Explorer wheel/buttons, ACK-looking motion bytes, framing/overflow/parity, actual 0/3/4 protocol negotiation with original libps2, failed-probe rollback and 1024 PS/2+USB button combinations. Actual-ISO UEFI and BIOS mixed-pointer guests prove rendered window drag survives switching physical transports and releasing the first held button. No physical compatibility result is inferred.

## Complete USB configuration core (v10)

The entire, byte-exact Linux v6.12 `drivers/usb/core/config.c` is compiled, not a function extraction. It implements configuration reads/caching/destruction, interface/alternate caches, duplicate endpoint filtering, endpoint interval/maxpacket repairs at the actual bus speed, SuperSpeed/SuperSpeedPlus companions and BOS capability parsing/destruction. GPL-2.0-only source and hash are pinned in the vendor manifest. All original functions compile through a separate private descriptor ABI; exported names are namespaced so these objects cannot accidentally be passed to the older bounded URB adapter. This is **not** a general Linux USB object ABI or complete USB core/HCD/hub/HID port.

Actual native xHCI/EHCI/UHCI enumeration now selects the configuration, hub class and HID alternate-zero endpoints from original Linux configuration caches, using the device's actual negotiated speed. Descriptor transport still starts with the native controller read; the synchronous core reader returns copies of those actual bytes, with actual short/error lengths, not synthetic successful hardware transfers. All cached configuration/interface/endpoint objects are destroyed after native endpoints have copied the selected parameters. Hub reset/power/child enumeration remains native: recognizing its class using Linux config.c is not porting Linux hub.c. Native enumeration retains its 1024-byte configuration/first-configuration and alternate-zero input policy.

A standalone opaque descriptor-core API also accepts a real descriptor-read callback and 1–8 configurations (the upstream cap), including BOS reads. It is not a substitute for Linux device registration, HCD lifecycle, enumeration messaging or generic HID. Its kernel services are real heap allocation/free, reference-counted cache release and PIT-channel-2 delay. Allocation is bounded by the native 64 KiB allocator; short configuration headers are rejected before upstream copies them. Zeroed tail padding protects optional descriptor lookahead without altering actual transfer lengths. The optional endpoint-ignore platform database is empty and not enabled; optional diagnostic formatting is replaced by bounded counters, not fake I/O or locks.

Host tests execute original config.c at freestanding O1/O2 with ASan+UBSan: partial allocation/transport rollback, short/oversized callbacks, configuration-count cap, alternate caches, duplicate endpoints, speed-aware repairs, SS/SSP companions, all BOS capability pointers and replacement/free, malformed BOS, 4096 deterministic configuration mutations, every truncated composite prefix and 1024 leak-free lifecycles. Guest tests additionally inspect original linked symbols and live descriptor-read/cache allocation/free counters, with nested hub profiles requiring one successful original-core parse for each hub and HID device. This remains virtual-device evidence only.


## Whole generic/input source milestone (v12)

`hid-generic.c` and `hid-input.c` are byte-exact whole Linux v6.12 files, not parser excerpts. `hid_generic_runtime.inc` compiles both, plus exact core report-bit, field/array event, ordering and output functions. Their private input ABI cannot alias the existing Boot input/USB ABI. The runtime has actual owned input objects, per-application registration, low-level start/open/close/stop callbacks, report dispatch to the required event sink, deferred LED work and real output/raw callbacks. Unsupported optional operations return negative errors; battery/FF/HIDRAW/HIDDEV are configuration-disabled. This is not the general Linux device/input core or complete HID bus.

The declared generic consumer policy bounds descriptors to 1024 bytes, frames to 16384 bytes, fields to 16 bits, per-device inputs to 16, signed ranges and unit exponents to checked values, and the aggregate parser heap to 2 MiB. Probe fails on allocation loss or unsupported models instead of returning a partial device. All runtime entry points share a nonblocking ownership gate: nested calls return busy; callbacks must not destroy their handle. Raw/output operations are explicitly synchronous; the deferred LED service runs outside interrupt context. Original hid-input uses Linux-equivalent signed-wrap compiler semantics.

O1/O2 freestanding ASan/UBSan execute original generic matching/probing, competing-driver preference, relative XY/five buttons/high-resolution wheel, keyboard modifiers/arrays/16-key bitmap/rollover, unchanged-state filtering, per-application composites, output/raw fallback and errors, every allocation rollback, transport/input registration failures, 1024 full lifecycles and 4096 descriptor mutations. Disconnect releases held keys and cancels queued work; all heap objects are freed.

**Active-production boundary:** the original generic/input symbols are compiled/linked in the v12 development kernel, but native endpoints still use Boot drivers or the v11 Linux-parser/native-packet bridge. Host event callbacks are not rendered native OS integration. Wiring native USB endpoints and Italian input/button ownership into this generic runtime is pending. Native controllers, enumeration and hub power/reset/lifecycle are unchanged; no HCD/core/hub completion or hardware certification is implied. PS/2 class drivers were not edited.
