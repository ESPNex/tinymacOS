# Linux USB/input compatibility — implemented boundaries

The requested complete Linux controller/core/hub port is **not finished**. PS/2 is excluded from the remaining scope by the latest user instruction. Recovery remains a separate OpenCore firmware input path. QEMU and host tests do not certify physical Bay Trail hardware.

## Current canonical kernel experiment (opt-in)

`TMC_USB_CANONICAL=1 bash build.sh` links complete original USB core/HCD/hub/common/buffer/port translation units against a single canonical USB/device ABI. `usbcore_bridge.c` reaches the original xHCI/EHCI runtimes through opaque handles and byte buffers, never struct aliases. The original Boot keyboard/mouse drivers bind through the original USB bus. The previous native class/enumeration path is not started in this mode; PS/2 is excluded. The default build retains the earlier separate private-ABI class facade described below.

The same dualboot experimental ISO passed **6/6 QEMU BIOS/UEFI cases**, including rendered USB keyboard login/Terminal, pixel-checked cursor, external hub, armed-URB hot unplug and same-port reattach. The original controller counters advance without errors and the old native class counters remain zero. Full original core/HCD/hub MODEL enumeration/teardown also passes O1/O2 ASan/leaks/UBSan; MODEL and guest evidence are separate.

This path uses whole original `usbkbd`/`usbmouse`, **not the complete canonical HID-core/usbhid stack**. It is serialized CPU0 polling, with sleeping USB work still draining in input/IRQ context. Only control and interrupt-IN transport is accepted. Further scheduler, initialization/endpoint rollback and reset coverage is required. The entropy ingestion hook has no connected kernel pool and credits no entropy. No physical IRQ, IOMMU, noncoherent DMA, system PM, physical-board or final release guarantee is made.

Receipts: `workspace/release-10.1.7-30B8/usbcore-kernel-integration-result.json` and its six `usbcore-dualboot-*` records. [Hardware live-test precautions](../../docs/HARDWARE-TEST.md). Source snapshots remain immutable when documentation later changes.

## Earlier/default private-ABI implementation

The remainder describes the default/private-ABI path and its earlier host contracts; it must not be read as denying the opt-in kernel integration above, or as claiming that opt-in usbhid is complete.

## Original Linux v6.12 code actually active

- Whole original UHCI HCD/queue/root-hub/PCI, EHCI HCD/queue/memory/schedule/root-hub/timer/PCI/sysfs-method units, and xHCI controller/memory/ring/hub/extended-capability/PCI/debug units. They own actual DMA schedules, bandwidth, toggles, completion and unlink; private adapters provide real PCI/coherent-DMA/poll/timer/lock services. Optional debug/PM paths are disabled through upstream configuration, not fake successful hardware operations.
- Original EHCI `HCD_BH` giveback functions and deferred hub TT-clear worker functions. BH givebacks run independently of sleeping TT work: immediate class resubmission must not occur under EHCI's schedule lock, and TT control waits must not block their own completion executor.
- Whole `mm/dmapool.c`, with original small-block allocation, page expansion, alignment/boundary handling, managed-pool entry points and poison diagnostics, used by original UHCI/EHCI. This is not a general IOMMU/noncoherent-DMA implementation.
- Whole `usbmouse.c`/`usbkbd.c`, core `urb.c`/`config.c`, `hid-generic.c`/`hid-input.c` and `libps2.c`.
- Complete original EHCI `qtd_fill`, psmouse packet/report and IntelliMouse/Explorer detector functions, and HID descriptor/event/output function groups.
- Complete original `message.c` synchronous control/send/recv/get-descriptor functions now run through original URB/HCD lifecycle for xHCI/EHCI/UHCI enumeration, configuration reads, hub requests and generic HID EP0. Whole message.c is vendored for audit but only the manifest-declared byte-exact ranges are compiled.
- Complete original `hcd.c` endpoint link/check/unlink, submission, unlink/refcount and direct-giveback functions now replace the manual lifecycle implementation.
- Complete original `hub.c` USB2 port debounce, reset-wait, warm-reset check and reset functions now run during native xHCI/EHCI hub-child enumeration. Actual EP0 bytes, checked short transfers, elapsed delays and CONFIGFLAG/reset reader/writer exclusion are provided by the native adapter.

`vendor/linux-v6.12/manifest.json` pins full upstream source hashes and verifies every function extraction byte-for-byte before build. Original notices remain intact. USB Boot/shim/HCD/hub code is GPL-2.0-or-later; core URB/config code is GPL-2.0-only; the input event header retains Linux-syscall-note.

## Native services and limits

The new DMA unit has its own private ABI, not an unsafe struct-device alias. Coherent allocations use real contiguous, page-order-aligned low-32-bit kernel memory; hardware links use the returned bus handle separately from CPU pointers. Current target is coherent identity-DMA x86-64 without an active IOMMU; allocations are bounded to 64 KiB. The original pools read attribute is registered in an actual native diagnostic registry (no Linux sysfs VFS claim); managed resources retain release callbacks and execute them in reverse order. Locks are IRQ-safe non-sleeping locks in this polled runtime, not a general sleepable Linux scheduler. The facade rejects invalid/duplicate frees and busy teardown. Failed controller slots are never reused while DMA state could be live; uncertain hardware-start failures retain their memory rather than freeing reachable DMA.

UHCI/EHCI/xHCI schedules and controller operations now execute whole original Linux drivers; the UsbInput enumeration/class boundary remains native and separate. A copying transport beneath original URB/HCD lifecycle functions supplies Boot interrupt-IN and keyboard EP0-OUT, with one active slot each and eight-byte payloads. Unsupported root-hub/SG/bulk/isoc operations fail explicitly. Separate message-only records support serialized synchronous EP0 IN/OUT up to 1024 bytes with real actual lengths, deadline/error handling and guarded detach. The shared pool has 128 records (Boot plus control), not unlimited Linux devices. Native callbacks must be bounded: late replies are rejected, but a callback cannot be preempted. Nested/concurrent control calls return -EBUSY, not fabricated success; generic output is deferred while another EP0 service is active. Boot keyboard LED URBs continue directly through the original HCD worker, without recursively entering synchronous message.c. These class transport objects are not themselves physical Linux HCDs or Linux root hubs; on UHCI/EHCI, their bounded transfer bridge reaches separate real original-HCD objects. Original HCD endpoint/state gates and callback/anchor/reference ordering remain active.

Generic HID uses the actual native endpoint/EP0 adapter and the whole original generic/input units, then registered shared native keyboard/pointer consumers. It is a separate private ABI, not an alias of Boot USB/input objects. Limits: 1024-byte descriptor, 64-byte packet, input-frame size checked against endpoint capacity, 32 bindings, 16 application inputs each, eight copied pending reports. It supports bounded relative/absolute pointers and keyboard applications; unsupported models fail attachment. Italian ISO/AltGr events and held keys/buttons merge with Boot/PS2 input. Deferred LED output, reentrant reports, errors, queue overflow and detach preserve ownership.

The descriptor core also exposes a separate opaque parser with the upstream eight-configuration cap and BOS support. Native enumeration currently chooses first configuration/alternate zero, with at most 1024 received bytes. Configuration/HID/Boot objects are deliberately not interchangeable.

Locks, allocation, references, timed predicate waits and callback I/O are real implemented services. Waits run in the current native polled runtime, not a general Linux sleepable scheduler. Optional usbmon/KCOV/LED-trigger/debug instrumentation is disabled; no hardware operation is replaced with a successful no-op. The extracted hub helpers accept SuperSpeed (5), reject SuperSpeedPlus (6), and do not implement full hub lifecycle/hotplug. SuperSpeed context/model checks are not physical SuperSpeed device validation. The original hub timing constants, including the 2000ms debounce cap, are retained.

## Still missing

In the experimental xHCI/EHCI path, canonical bus/root-hub/full hub enumeration and hotplug now execute. Complete the canonical HID-core/usbhid path and scheduler/rollback/reset work before enabling it by default. The default/private path remains separate; the canonical experiment does not cover UHCI. General SG/bulk/isoc/DMA services, hardware IRQ routing and system PM are not certified by the polled controller tests. Whole-original controllers on private ABIs are not proof of a complete Linux USB stack. PS/2 completion is not a release requirement. Source integration is not a completed release or deployment.

## Verification

ASan/UBSan contracts execute original code and actual adapters: synchronous message/descriptor send/recv, malformed descriptors, exact versus short reads, late timeout/stale-copy protection, queued cancel, cross-thread serialization, 128-record exhaustion, reference/anchor/cancellation races, endpoint state/queue gates, unlink-status precedence, callback resubmit/free, allocation rollback, Italian/mixed input, generic report/LED/reentry handling, USB2 bounce/reset/error/timeouts and CONFIGFLAG writer exclusion. Actual ISO guests compare KernelCache to the build, observe non-secret upstream/native counters and independently check rendered input. Current receipts and remaining gates live in `workspace/release-10.1.7-30B8/STATUS.json`; older receipts only certify their recorded hashes.


### EHCI v18 regression

`python3 ../workspace/release-10.1.7-30B8/linux-ehci-contract.py` executes the exact original scheduler on nonidentity DMA with O1/O2 ASan/UBSan: control, full/short/STALL interrupts, cancellation, timeout, EP0 address/QH reinitialization, 16 immediate completion resubmissions, HS-hub/FS-child TT work and 38 initialization-allocation failures. The DMA controller contract additionally runs 128 complete original-EHCI controller/device lifetimes. UBSan alignment alone is excluded for upstream list sentinels; actual DMA alignment remains asserted. This is not physical-board, hardware-IRQ, complete hub/usbhid or release acceptance.

### Canonical USB ABI development contract

`bash tests/test-linux-usbcore.sh` runs two host executables at O1/O2 with heap/stack/leak ASan and UBSan including alignment. Exact upstream `usb.c`, `driver.c`, `generic.c`, `quirks.c`, `config.c`, `urb.c`, `hub.c`, `message.c` and `endpoint.c` compile against the SAME original `linux/usb.h` and `linux/usb/hcd.h`, with one service `struct device` model. The new code is in `usbcore_services.c` and `usbcore-include/`; it is now selected by the opt-in kernel build via `tools/build-usbcore.sh`; defined canonical symbols are namespaced and undefined dependencies allowlisted to prevent accidental cross-ABI linkage.

The first executable exercises original descriptor/configuration parsing and allocation-failure unwind, matching/version/interface lookup, hub ownership queries and URB references. Its descriptor transport is an explicit host fixture. The second exercises original USB driver registration/probe/unbind, authorization rejection, failed-probe managed rollback, dynamic-ID attributes and fourteen registration allocation-failure positions. Its HCD/notification entry points are test-only aborting tripwires: any USB I/O fails the test, never succeeds as a no-op. Those two ABI/binding executables alone claim neither hub enumeration nor usbhid execution; separate MODEL/guest receipts cover hub runtime. ASan global registration alone is disabled to permit dead-section elimination of uncalled upstream tables; the compiled whole files are not all called.

The shared services implement device/driver registries, parent/reference ownership, mutation-safe device iteration, managed release, attributes/unnamed groups, bounded allocations/reallocation, separate BH progress and serialized sleeping workers, delayed work, timers, callback-owned frees, completion deadlines and UTF-16 decoding. They require explicit OS hooks. Named/visibility-dependent metadata groups return an error; this is an internal metadata registry, not a Linux sysfs VFS. It is a serialized CPU0 service layer, not an SMP/preemptive Linux scheduler; recursive blocking on an owned mutex is rejected. The separate physical bridge now connects root-hub and class URBs to the original controllers; full canonical HID lifetime remains to be integrated.

The additional exact upstream inputs are independently pinned in `vendor/linux-v6.12/usbcore-manifest.json`, leaving the v19 production provenance file unchanged. Use `TMC_USBCORE_RECEIPT=...` to write dependency/source-bound evidence. This receipt is separate from the v19 ISO/controller matrix and cannot authorize a release or change the v19 matching-source archive.
