# Linux USB compatibility — implementation status

The kernel compiles the complete, unmodified Linux v6.12 Boot drivers **`usbmouse.c` and `usbkbd.c`**. `vendor/linux-v6.12/manifest.json` pins source and license hashes; upstream notices remain intact. The keyboard translation unit includes the byte-exact driver and exposes its physical keycode table to the input adapter. The port is GPL-2.0-or-later.

Implemented runtime services: allocation/failure cleanup, coherent one-page buffers, logical interrupt URB submission/completion/synchronous cancellation, input device lifetime, relative events and physical keyboard state. Native imports provide IRQ-safe serialization, heap/pages and actual input events; a userspace POSIX libc alone cannot supply kernel DMA, IRQ or URB services. The string/format subset uses bounded writes and ordinary return/termination rules.

Native xHCI/EHCI/UHCI enumeration passes real received interrupt packets to the upstream Boot drivers. Mouse report IDs, wide axes, nonstandard wheel layouts and absolute tablets retain the descriptor-aware native path; they are **not** Linux generic HID support. Allocation failure retains the native fallback. Keyboard events use the sole Italian physical layout, not upstream US Unicode assumptions; registered Linux keyboards merge their held-key bitmaps and modifiers without a six-key aggregate limit. Invalid/rollover reports do not invent releases.

The actual upstream keyboard LED event/completion path submits a logical control URB. A bounded service routine copies it, drops the compatibility lock and invokes the existing native EP0 transport. It checks binding generation and submission serial before completion, preventing use-after-free and ABA on cancellation/disconnect/rebind. This is an adapter, **not the Linux general URB/HCD machinery**. Only the required bounded OUT control subset is implemented. Platform suspend/wake enable is explicitly unsupported.

The complete byte-exact Linux EHCI `qtd_fill` function is also used in native EHCI DMA descriptor construction. Source validation checks its full extraction before every build. This is not the Linux scheduler.

**Not yet ported:** Linux xHCI/EHCI HCDs, general USB core/hubs and generic HID. No claim of a full Linux USB stack or release completion. Recovery stays separate: firmware mouse protocols, OpenUsbKbDxe keymap and the declared derived firmware PS/2 raw stream.

Tests: `tests/linux_usbmouse.c` and `tests/linux_usbkbd.c` execute the upstream drivers and real shim under ASan/UBSan. Keyboard tests include actual native Italian input, seven allocation rollbacks, multi-keyboard state, repeat/caps, cancellation, LED changes, reentrant native control, cancellation/resubmit and disconnect/rebind during control, STALL and leak-free teardown. Existing native HCD host contracts link the same shim. Guest receipts in `workspace/release-10.1.7-30B8/` identify the actual ISO and read live upstream completion/control counters, with rendered Italian input checked on EHCI, UHCI companion and xHCI hub under UEFI and BIOS. QEMU is not physical Bay Trail validation.
